# GTNH Line Planner — architecture and cross-plan contracts

**Read this first.** The build is split into five plans that each ship working, tested software. This document fixes everything two plans must agree on: repo layout, tooling, names, units, shared types, module boundaries, HTTP API and SSE events. A plan may add private helpers freely, but it must not rename or reshape anything defined here. If a plan needs a change here, the change is made here first.

- Spec: `docs/superpowers/specs/2026-10-17-gtnh-planner-design.md`
- Research (facts with evidence): `docs/research/*.md` — export-mod, world-format, gt-mechanics, textures-icons, web-stack, prior-art, materials-availability
- Local-only facts (paths, world scan): `docs/local/*.md` (gitignored, never commit)

## 2. Hard rules (every plan)

1. **Never touch the live server.** No start/stop, no writes to its folder. The exporter runs only on an APFS clone under `.local/export-server/` (port 25566 on 127.0.0.1). World reads are read-only; prefer the newest *complete* backup zip, or copy region files to a snapshot before reading.
2. **Nothing game-derived or private is committed**: exports, textures, icons, world scans, uploads, project DB, config/password, local notes. All of it lives under `data/` or `.local/` or `docs/local/` (gitignored). Tests use synthetic fixtures generated by test helpers, never real game files.
3. Code is TypeScript (erasable syntax only) and Java only inside `exporter-mod/`. MIT license.
4. Node `>=24.10.0 <25`. Add/upgrade npm deps only with `npm install --save-exact --before="$(date -v-14d +%F)" <pkg>@<ver>`; commit `package-lock.json`.
5. Commits: conventional (`feat:`, `fix:`, `test:`, `docs:`, `chore:`), each ending with the line `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## 5. Vocabulary and units

| Thing | Rule |
|---|---|
| Item key | `${registryName}@${meta}` e.g. `gregtech:gt.metaitem.01@2032`; NBT-sensitive variants append `#${first 12 hex of sha1(SNBT)}`. Wildcard meta 32767 never appears in a key (it is expanded to alternatives at load). |
| Fluid key | `fluid:${fluidRegistryName}` e.g. `fluid:molten.iron` |
| Stuff key | `ItemKey \| FluidKey` (`StuffKey`) — every planner node |
| Machine id | GT MTE id (`mteId`, number) — same as world `mID`. Non-GT "machines" (crafting table, furnace) use the pseudo ids in `PSEUDO_MACHINES` (§6.1). |
| Recipe id | content hash: first 16 hex of sha1 over canonical JSON (Plan 1 `recipe-id.ts`), stable across re-exports |
| Recipe map id | GT `unlocalizedName` after alias normalization (`map-aliases.ts`); pseudo maps `crafting`, `furnace`, `assemblyline` |
| Tier | integer 0..14 = ULV, LV, MV, HV, EV, IV, LuV, ZPM, UV, UHV, UEV, UIV, UMV, UXV, MAX; `V[t] = 8·4^t` (t ≤ 13), `V[14] = 2147483640` |
| Amounts | items in items; fluids in litres (L) |
| Rates | per second internally (`perSecond`); UI converts to /min or /h |
| Energy / time | EU/t, ticks (20 t = 1 s) |
| Dimension | Minecraft dimension id (number); folder name `DIM<id>` (Overworld = 0 has no folder prefix) |
| Position | world block coords `[x, y, z]` + `dim` |
| Material cost | ingot-equivalents: GT material forms cost `costPerIngot(material) × prefixAmount / M` (M = 3628800); molten fluid `costPerIngot × L / 144`; other fluids `1 per 1000 L`; other items 1; free: `fluid:water`, `fluid:lava`, `fluid:air` (and GT air variants listed in Plan 2), cobblestone. Per-project overrides by material name or by key. |

(a) Resolver order — block faces: GT dump block table (a meta whose six faces are all empty after dropped layers counts as absent) → GT ore block → GT material block (frames, sheetmetal, storage blocks from the pack's `gt {prefix, material}`) → curated table → the dump's texture name (exact, then face-aware suffix probing) → the file-name rule (`src/server/assets/names.ts`) → none. Icons: NEI → for fluids: GT still → the fluid block's texture (0.4.0 `fluids[].block`) → fluid file by name → GT `fluid.autogenerated` tinted → none; for items: GT meta item → GT material template (metaitem.98/99, BartWorks) → curated item table → item texture name (exact, then probing) → file-name rule (items atlas, numbered `<name>/<meta>` first; skipped for a block id) → block faces → fallback. A rule only ever picks a square file or an animation strip; items look in `items/` before `blocks/`; in `items/` a registry name never loses a trailing `Block` or `_block` (only `Item` or `_item`), so a block's item never takes its material's item icon; a block id — an id the dump's `blockIds` lists, which includes every ItemBlock — never takes an `items/` file through the file-name rule, in its own domain or any other: block ids use only the `blocks/` rules, their item texture name and the curated rows; a basename or case-insensitive match counts only when it is the only one; the block and item name rules also run without a dump (the mod id as the only domain, and no id counts as a block id), the fluid rules only with one. (b) `TextureLayer.region?: LayerRegion` = `{ sheet: number; src: [x, y, w, h]; dst?: [x, y, w, h] }`: `src` in pixels of a sheet `sheet` pixels wide (scaled to the file's real width), `dst` in sixteenths of the tile (default the whole tile); clients crop `src`, draw it at `dst`, and key every image cache by path and region. (c) `BlockFaces.pipe?: PipeLayers` = `{ core; arm; end: TextureLayer[] }` for blocks drawn as a core with arms: the 3D view draws the core with `core`, an arm's tip with `end` and its long faces with `arm` (u along the arm), every textured pipe tile over its block role's plain colour; curated pipes carry crops of their model sheets, GT pipes their unconnected side (exported or derived). (d) Animated textures have square frames: `frames = floor(h / w)`, as Minecraft 1.7.10 cuts them. (e) The extractor also copies `minecraft/textures/entity/chest/*.png` and `ironchest/textures/model/*.png`. (f) `POST /api/pack/names` `{ keys: StuffKey[] }` (at most `ASSET_KEYS_MAX`) → `Array<string | null>` in request order. (g) `textures.json.gz` from exporter 0.4.0 (format unchanged, every field optional): `mte[].unconnected`, `fluids[].block`, `prefixTextures`, `fluids[].still` following `iconsFrom` first, `metaItems` rows for the Programmed Circuit and GGFab's `gt.ggfab.d1`, `blocks` rows for GT storage, frame and sheetmetal blocks. (h) Icons scale evenly: an upscale that is not a whole multiple goes nearest-neighbour to the next whole multiple, then smooth to the target; a downscale is smooth. A region crop is scaled nearest-neighbour to its place in the tile. (i) Optional: `AppConfig.clientInstance` and `AppConfig.useResourcePacks` (default `false`) overlay the client instance's enabled resource packs on the jar textures, `options.txt` order, last wins. (j) `orientFaces(faces, facing)`: a block facing up or down whose four sides share their first layer keeps every world side's own canonical layers (BOTTOM, TOP, SIDE hulls with their overlays), except that the facing side draws its own hull under the front's (canonical north's) overlays and world north draws its hull alone, as `MTEBasicMachine.getTexture` does with a vertical main facing; every other block turns whole (`rotateFaces`).
