# Line Layout & 3D Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Place the planned line in the group's world — a clear site near the base and its tap-ins, a compact arrangement for the project's logistics mode, power and logistics hookups that never overvolt a machine or overload a cable, numbered pins, build steps and a power-fit verdict — and show that one layout on the map and in a textured 3D view.

**Architecture:** A pure server module `src/server/layout/` turns `(Pack, Plan, WorldScan, Project)` plus voxels read through Plan 4's `readArea` into one `Layout` (architecture §6.7): site finder → arrangement per logistics mode → A* hookups with cable and transformer choice → pins, parts list, build steps and power fit. A layout service caches the result by plan settings hash + scan id + placement and serves `GET /api/projects/:id/layout`; the SSE `plan` event already means "plan and layout may have changed". The client draws the same `Layout` as a map overlay with numbered pins and drag-to-move placement, and in a three.js `View3D` tab (one `DataArrayTexture` of block faces, one `InstancedMesh` per block shape, OrbitControls, layer slider, hover label, click panel, ghost blocks, block list). The plan route stays Plan 2's; Plan 2 ships the hooks (architecture §11.15–§11.16: `planForProject`, `app.services.planFinish`, the `plan` event after placement ops, `expandBomLines`) and this plan only sets `planFinish`, so the layout fills `Plan.power.fits`/`suggestions`, adds its grouped parts to the build list and puts its pin-linked steps into the build steps. Every cover, filter, chip and pattern is data on its host block (`CoverSpec`, `config`, architecture §11.14) from which the configure steps, the map marks and the 3D cover plates are all generated.

**Tech Stack:** TypeScript 6.0.3 on Node 24 (type stripping), React 19.3.0, three 0.186.1 (+ @types/three 0.186.0), vitest 5.0.3, @playwright/test 1.63.0.

**Spec:** `docs/superpowers/specs/2026-10-17-gtnh-planner-design.md` (§3.5, §3.6, §3.7, §3.8, §3.10). Contracts: `docs/superpowers/plans/2026-10-17-00-architecture.md` (§2, §5, §6.6, §6.7, §7, §7.1, §7.2, §8, §10, and §11.13–§11.17, which amend them and win on conflicts). ## Global Constraints

- Node `>=24.10.0 <25`; TypeScript erasable syntax only (no `enum`, `namespace`, parameter properties, decorators, `<T>x`); relative imports name the real `.ts`/`.tsx` file; type-only imports use `import type`; enums are `as const` objects.
- Dependencies: only architecture §4 pins. This plan uses `three@0.186.1` and `@types/three@0.186.0`; if missing, `npm install --save-exact --before="$(date -v-14d +%F)" three@0.186.1 @types/three@0.186.0` and commit `package-lock.json`. OrbitControls is imported from `three/addons/controls/OrbitControls.js` (same package). No other new dependency.
- Never touch the live server (architecture §2.1, spec §4): the layout only reads voxels through Plan 4's read-only `readArea`; nothing here writes to a world or server folder.
- Tests use synthetic fixtures built by `tests/helpers/` (architecture §10); checks against a real export or world run only with `GTNH_LOCAL=1`.
- Coordinates are world block coordinates `[x, y, z]` + `dim`. `Layout.origin` is the minimum corner of the line's bounding box; `Layout.size` is `[W (x), H (y), L (z)]`; `Project.placement.origin` names the same corner.
- Facing numbers are ForgeDirection: down 0, up 1, north 2 (−z), south 3 (+z), west 4 (−x), east 5 (+x). Rotation is clockwise seen from above: 90° turns north → east → south → west.
- Never overvolt (spec §3.5, gt-mechanics §3.4): every powered block a layout places receives packets of at most `V[its tier]` volts, where arriving volts = source volts − Σ `cable.lossPerBlock` along the path.
- Never overload a cable (gt-mechanics §3.3): every cable run has `voltage ≥` the packet volts it carries and `amps ≥` Σ `ceil(euPerTick / V[tier])` over the machines it feeds (plus the transformer banks' input amps); when no cable in the pack is big enough, the layout says how many parallel runs to lay (`cable_amps`), and runs that lose more than 10 % of their volts are flagged (`cable_loss_high`).
- Transformers (gt-mechanics §3.6): a placed transformer is in step-down mode, takes `V[t+1]` on its front face only (≤ 2 A in) and gives `V[t]` on its five other faces (≤ 4 A out); every emitter hop costs `2^max(0, t−1)` EU per amp (gt-mechanics §3.2).
- Power fit (spec §3.5 "my call"): `yes` when `spareEUt ≥ need` and `storedEU ≥ need × 20 × rainOutageSeconds`; `tight` when only the first holds; `no` otherwise; `need` = the line's average EU/t + cable loss + transformer loss. Generators are suggested in text and as optional parts, never placed.
- Multiblocks use their exported `Machine.structure` size and keep its `air` cells empty (gt-mechanics §5.3).
- Logistics mode comes from `project.settings.logistics` (`direct` default, `routed`, `ae2`); a layout never silently assumes a network or storage the scan did not find (spec §5).
- Determinism: the same inputs give byte-identical `Layout` JSON (fixed sort orders and tie-breaks), so map, 3D view, block list and cache agree (spec §3.8 "they always agree").
- 3D (web-stack §8): three.js `WebGLRenderer` with a `ShaderMaterial` sampling a `DataArrayTexture` through `sampler2DArray` — never `glslVersion: THREE.GLSL3`; V flipped in the shader; `NearestFilter`, no mipmaps, `SRGBColorSpace`; render on demand (no animation loop, the host also runs the game); the 3D tab is lazy-loaded. Textures come from `POST /api/assets/blocks`, `POST /api/assets/icons`, `POST /api/assets/covers` and `GET /api/assets/file/<path>`, loaded through Plan 3's `loadLayerBitmap` and blended with its `compositeLayers` (icons and 3D faces blend alike); a face that cannot be resolved is a plain colour (spec §3.8).
- Bounded work on the server: the site search reads at most a `MAX_SITE_SPAN` (192) block square around the base, and every A* search stops after `MAX_PATH_NODES` (200,000) expansions.
- Configured parts (architecture §11.14): a cover is never a block of its own — it is a `CoverSpec` on the block it sits on (`LayoutBlock.covers`); programmed circuits, machine input filters, routing chips and AE2 patterns are `LayoutBlock.config`. Every configured block gets a `configure` build step stating the exact settings (cover item, face, mode/direction, rate, whitelist or blacklist with item names, chips, circuit number), produced from that data by one shared formatter (`src/shared/layout/configure-text.ts`, Task 10) that the 3D hover and click info also use. The map overlay marks configured blocks; the 3D view draws each cover on its face.
- Sizing (architecture §11.13): cables by volts and amps (`Machine.cable`), pipes by `Machine.itemPipe`/`fluidPipe`, conveyor and pump covers by `COVER_RATES` (Task 3) at or below the plan's tier (warning `cover_rate` when none carries the flow), input/output buses by slots `(tier + 1)²`, fluid hatches by capacity `8000 × 2^tier` L. The idle draw of placed ME parts (`ae2IdleEUt`) is added to the line's power before the power fit.
- Parts list groups (architecture §11.13): every `Layout.bom` line has `group` — `power` (cables, transformers, power hookup, generator suggestions), `logistics` (pipes, covers, ME interfaces and cable, routed pipes, chests, chips, blank patterns, filters, logistics hookup), `machines` (hatches; `Layout.replaced` casings).
- Tap safety (spec §3.5, §5): a hookup cable is never laid onto a tap whose cable carries fewer amps than the line draws; that hookup stays a dashed guide with warning `power_amps_low` and an upgrade build step.
- Commits use a conventional prefix and the message ends with the line `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **A project with no target, no world scan or no base yet** (a friend planning before anyone uploaded a world): `GET /api/projects/:id/layout` still answers 200 with a layout at a default origin, no hookups and a warning that says to pick a scan; the map and 3D tabs show that warning instead of crashing. Tests: Task 11 "lays out without a scan", Task 12 route test.
2. **No clear space near the base** (dense base, a lake, lava, a hillside): nothing is placed into existing blocks silently; the layout takes the best fallback spot outside the base box and adds warning `site_not_clear` plus a `warning` pin with the number of blocks in the way. Tests: Task 4 "treats water and lava as unbuildable", "falls back outside the base when nothing fits", "never builds on scanned blocks or GT machines".
3. **Power the base cannot deliver safely**: no power network, only a lower voltage than the line's machines, or a tap whose cable carries fewer amps than the line draws — never a connection above a machine's tier or onto a cable it would burn; warning `power_tier_low` / `no_power_tap` / `power_amps_low`, an upgrade step and generator suggestions. Tests: Task 3 "says so when the base has no power network", Task 6 "wires a machine above the supply tier to the supply run and warns", Task 9 "never lays a hookup onto a tap whose cable carries fewer amps than the line draws".
4. **A hookup path that is blocked or far away** (walls, a tap 200 blocks off): the path search stops within its node budget and returns a straight dashed fallback with warning `no_path`, without stalling the server. Tests: Task 2 "gives up within its node budget", Task 9 "falls back to a straight dashed guide when no route exists".
5. **A dragged placement that overlaps the base, sits underground or above the build limit**: x and z are kept, y is clamped to `1 … 256 − H`, and warning `placement_blocked` reports how many solid blocks are in the way. Tests: Task 4 "checks a user placement", Task 11 "honours a dragged placement and says what is in the way".

## How a layout is built (read once; every task refers to it)

`layoutLine` runs these stages; each task owns one.

1. **Context** (Task 11): base = `findBase(scan, project.world.baseId)`; `ctx = contextFromScan(scan, pack, baseId)`; choose the power network and the logistics network (Task 9).
2. **Units** (Task 5): one unit per *new* machine (`count − owned`) of every placed step; multiblocks take their exported `structure` and get hatch cells.
3. **Placement** (Task 5): a local grid (x = along the line, z = across, y = up). Two rows of units face a one-block **spine** (z = `spineZ`, y = 0); x = 0 … `headWidth − 1` is the **power head** (cable runs and transformer banks); x = `tailX` is the **tail** (chests, request pipe, fluid roots). Row N fronts face south, row S fronts face north.
4. **Mode** (Tasks 7–8): what sits on the spine and the tail — a shared GT item pipe (direct), Project Red routed pipes (routed) or ME cable with interfaces (AE2) — plus the covers (`HostCover`) and settings (`HostConfig`) it puts on machines and on its own blocks.
5. **Internal routing** (Task 6): power head + cable trees from each tier's run to every unit, GT fluid-pipe trees per fluid with sized pump covers; all with the A* router (Task 2). Covers and settings are then attached to their host blocks (`attachCovers`, Task 5).
6. **Site** (Task 4): the local box (W × H × L) is placed in the world — searched near the base and the taps, or taken from `project.placement`.
7. **Hookups** (Task 9): A* over the world voxels from the chosen taps to the line's power head and logistics port; ghosts of the existing blocks touched.
8. **Pins, parts, steps, power fit** (Tasks 10, 3): numbered pins, the grouped parts list, build steps linked to pins (one `configure` step per configured block), AE2 idle draw, `fits`/`suggestions`.

```
 local z ↓   x →   0      1 … (units) …            tailX
 0  lane        [run]   ·  ·  ·  ·  ·  ·  ·          ·
 1  row N       [run]  [M][M][M][M][M]               [in chest]
 2  spine       [run]  [=][=][=][=][=][=][=][=][=]   [port]
 3  row S       [run]  [M][M][M][M]                  [out chest]
 4  lane        [run]   ·  ·  ·  ·  ·  ·  ·          ·
```

- Produces (`src/server/layout/path.ts`):
  ```ts
  export const MAX_PATH_NODES = 200_000;
  export interface PathBounds { min: Vec3; max: Vec3 }                     // inclusive
  export interface PathOptions { passable(p: Vec3): boolean; bounds: PathBounds; maxNodes?: number /* MAX_PATH_NODES */; verticalCost?: number /* 2 */; turnCost?: number /* 0.25 */ }
  export interface PathResult { found: boolean; path: Vec3[] /* start … goal, inclusive; [] when not found */; expanded: number }
  export function findPath(starts: readonly Vec3[], goals: readonly Vec3[], opts: PathOptions): PathResult;
  export interface TreeResult { cells: Vec3[] /* new cells in the order added */; links: Array<[Vec3, Vec3]>; unreached: Vec3[] }
  export function growTree(roots: readonly Vec3[], terminals: readonly Vec3[], opts: PathOptions): TreeResult;
  export function straightPath(from: Vec3, to: Vec3): Vec3[];             // x first, then z, then y; inclusive
  export function linkBits(links: ReadonlyArray<[Vec3, Vec3]>): Map<string, number>;   // posKey → bits 1 << side
  ```

Rules (the search must be deterministic, because the map, the 3D view and the cache must agree):
- `findPath` is a multi-source, multi-goal A*. A state is `(cell, side of the move that entered it)`; starts have no side. A cell may be entered when it is inside `bounds` and `passable(cell)` is true **or** it is a goal. Move cost = 1 horizontally, `verticalCost` for sides 0/1, plus `turnCost` when the side differs from the previous move's side. Heuristic = distance to the goals' bounding box (`dx + dz + verticalCost·dy`, admissible). The open list is a binary heap ordered by `(f, h, insertion number)`; neighbours are pushed in `DIRS` order. Each pop counts as one expansion; once `expanded > maxNodes` the search stops with `found: false`. A start that is a goal returns `[start]`.
- `growTree` keeps a set of tree cells (initially `roots`). Terminals are handled in order of (Manhattan distance to the nearest root, `posKey`). A terminal already in the tree is skipped; one that is not `passable` is unreached. Otherwise `findPath([terminal], treeCells, { …opts, passable: p => opts.passable(p) && !inTree(p) })`; on success every path cell except the last (an existing tree cell) is added to the tree and to `cells`, and each consecutive pair of the path becomes a link; on failure the terminal goes to `unreached`.
- `linkBits` sets, for every link `[a, b]`, `1 << sideToward(a, b)` on `a` and the opposite bit on `b`.

- `ae2IdleEUt` (research §3.8, AE2 rv3-beta-1073-GTNH): `AENetworkProxy` idles at 1 AE/t unless a part changes it; `PartCable` sets 0; ME Interface and ME Export Bus keep 1; `PowerRatios.IC2 = 2.0` means 1 EU = 2 AE, so `ae2IdleEUt` = Σ AE/t ÷ `AE_PER_EU`.
- `pickCable`: candidates are `kind 'cable'` machines with `cable.voltage ≥ volts`; prefer those with `cable.amps ≥ amps` (`ampsShort: false`), else take the highest-amp one (`ampsShort: true`); order insulated first, then `lossPerBlock`, then `voltage`, then `amps`, then `mteId`, all ascending. Bare wires shock players (gt-mechanics §3.3), so an insulated cable always wins.
- `pickItemPipe` / `pickFluidPipe`: the smallest `itemPipe.stacksPerSecond` / `fluidPipe.litresPerSecond` that is ≥ the rate (ties `mteId`), else the largest. `pickTransformer`: `kind 'transformer'` with `tier === lowerTier` (gt-mechanics §3.6: a transformer's tier is its lower side), class simple name `MTETransformer` first, then `mteId`. (`pickHatch` is above.)
- `tierGroups`: one group per tier; `amps = Σ ceil(euPerTick / V[tier])` over its machines (gt-mechanics §3.1 "count ceil(EU/t ÷ volts) amps per machine").
- `transformerStages` (step-down only, gt-mechanics §3.6): groups above `supplyTier` go to `under` (fed the supply voltage; Task 6 warns). `need[t]` starts as the amps of the group at tier t; for k from the lowest group tier up to `supplyTier − 1` with `need[k] > 0`: `ampsOut = need[k]`; `ampsIn = ceil(ampsOut × (V[k] + 2^max(0, k−1)) / V[k+1])` (emitter loss, gt-mechanics §3.2); `count = max(ceil(ampsOut / 4), ceil(ampsIn / 2))` (4 A out, 2 A in per transformer); `need[k+1] += ampsIn`; `lossEUt += ampsOut × 2^max(0, k−1)`. `supplyAmps = need[supplyTier] + Σ` over `under` machines of `ceil(euPerTick / V[supplyTier])`.
- `fitPower` (spec §3.5, Global Constraints): `need = power.averageEUt + extraLossEUt`. With `ctx.power`: during rain the buffers carry the base's own load as well as the line, less what still generates — `rainNeed = max(0, need + (averageEUt − spareEUt) − (rainEUt ?? 0)) × 20 × rainOutageSeconds` (`averageEUt`, `spareEUt`, `rainEUt` from `ctx.power`; a missing `rainEUt` counts as 0, so an older context errs towards `tight`); `fits = spareEUt ≥ need ? (storedEU ≥ rainNeed ? 'yes' : 'tight') : 'no'`; `detail = "Needs <need> EU/t on average (<average> + <loss> loss); <spare> EU/t spare"` plus `"; buffers hold <stored> EU, rain needs <rainNeed> EU"` when `rainOutageSeconds > 0`; suggestions: `no` → the generator text for `need − spare` at `ctx.power.voltageTier` (its lines go to `optional`), `tight` → `"Add battery storage: about <rainNeed − stored> EU more to ride out <round(rain / 60)> min of rain"`. Without `ctx.power`: `no`, `"No power network found at this base; the line needs <need> EU/t on average"`, generator text for `need` at `input.tier`. All numbers through `fmtInt`.
- `generatorSuggestion(pack, S, T)` (spec §3.5 "or other generators available at their tier"): turbine = lowest-`mteId` `kind 'turbine'` with tier T; none → generator = lowest-`mteId` `kind 'generator'` with tier T: `n = ceil(S / (V[T] × (amps ?? 1)))`, text `"Add about <n>× <generator> to cover <S> EU/t"`, lines `[{ key: generator.itemKey, amount: n, why, group: 'power' }]`; neither → `"Add generators for about <S> EU/t at <TIER>"`, no lines. Turbines `nT = ceil(S / V[T])`. Boiler = `kind 'boiler'` with `steamPerSecondMax`, class simple name `MTEBoilerSolarSteel` first, then the highest average steam, then `mteId`; average steam per boiler = `steamPerSecondMax × hotFraction × (1 − RAIN_OUTAGE_FRACTION)` for classes in Plan 4's `SOLAR_BOILERS`, else `steamPerSecondMax`; boilers `nB = ceil((S / V[T]) × turbineSteamForFull(T) / perBoiler)`. Text `"Add about <nB>× <boiler> and <nT>× <turbine> to cover <S> EU/t"`; lines `[{ key: boiler.itemKey, amount: nB, why, group: 'power' }, { key: turbine.itemKey, amount: nT, why, group: 'power' }]` with `why = "optional: covers a <S> EU/t power shortfall"`; `<S>` through `fmtInt` in text and why. Generators are never placed (spec §4).

  ```ts
  export const SITE_CLEARANCE = 1;      // free ring around the line
  export const MAX_STEP = 1;            // a column may sit 1 above or below the floor (dug or filled)
  export const MAX_SITE_SPAN = 192;     // x/z span of the voxel read (stays far below MAX_AREA_VOXELS)

  export interface Footprint { w: number; h: number; l: number }            // local W (x), H, L (z), before rotation
  export interface SiteRequest {

  }
  export interface Site { origin: Vec3; rotation: Rotation; size: Vec3 /* world */; floorY: number; dig: number; fill: number; blocked: number; unsupported: number; score: number; reason: 'search' | 'placement' | 'fallback'; moved: boolean }

  export function fallbackSite(req: SiteRequest, vox: Voxels | null): Site;
  export function checkPlacement(req: SiteRequest, vox: Voxels | null, placement: { origin: Vec3; rotation: Rotation }): Site;
  ```

Rules:
- Replaceable (counts as air): `minecraft:air`, `tallgrass`, `double_plant`, `red_flower`, `yellow_flower`, `deadbush`, `snow_layer`, `vine`, `fire`, `brown_mushroom`, `red_mushroom`. Fluid: `minecraft:water`, `flowing_water`, `lava`, `flowing_lava`, or any id matching `/fluid/i`.
- Column top: scanning down from the top of the voxel box, the first cell that is neither air nor replaceable. The column is **ground** when that cell is known (not `UNKNOWN_INDEX`), not a fluid, has no `mteId`, and its posKey is not in `avoid`. Columns with no such cell, unknown cells, fluids, GT tiles or scanned blocks are never ground.
- `baseFloorY`: the most common `pos[1]` of `scan.machines` with `baseId === base.id` (ties → lower), else `base.center[1]`.
- `siteSearchBox`: x/z = the base box ± `SITE_MARGIN`, grown to include every tap ± 2; y = `[floorY − 1 − SITE_HEADROOM, floorY + footprint.h + SITE_HEADROOM]` grown to every tap y ± 2, clamped to 0…255; an x or z span above `MAX_SITE_SPAN` becomes `[center − 96, center + 95]` around the base centre (taps outside it are reached by the straight fallback in Task 9).
- `findSite` tries every rotation for every `(x0, z0)` whose rectangle (rotated W × L) plus the clearance ring lies inside the voxel box. A rectangle is valid when all its columns are ground, `y0` = their most common top height (ties → lower) and every column is within `MAX_STEP` of `y0`, every ring column is ground with top ≤ `y0 + MAX_STEP`, and `y0 + footprint.h ≤` the box's max y. `origin = [x0, y0 + 1, z0]`; `dig` / `fill` = Σ of tops above / below `y0`. Score (lower wins) = `2 × manhattan(centre, base.center) + manhattan(power port, power tap) + manhattan(logistics port, logistics tap) + 4 × |origin.y − baseFloorY| + 2 × (dig + fill)`, where `centre = [x0 + floor(W'/2), origin.y, z0 + floor(L'/2)]`, ports go through `toWorld(port, origin, rotation, [w, h, l])` and a term is 0 when its port or tap is missing. Iterate `x0` ascending, then `z0`, then rotations `0, 90, 180, 270`, keeping only strictly better scores, so ties go to the lowest x, then z, then rotation.
- `checkPlacement`: x and z from the placement, `y` clamped to `1 … 256 − footprint.h` (`moved` when clamped), the given rotation; `blocked` = known cells inside the line's volume that are neither air nor replaceable (fluids count); `unsupported` = rectangle columns whose cell at `y − 1` is known and air, replaceable or fluid; `dig`/`fill` against floor `y − 1`; `score 0`. With `vox === null` every count is 0.
- `fallbackSite` (spec §3.6, Review Focus 2: never placed into blocks silently): rotation 0, `origin = [base.bbox.maxX + 1 + SITE_CLEARANCE, baseFloorY, base.center[2] − floor(l / 2)]`, counts as in `checkPlacement`, `reason 'fallback'`.

Rules:
- `stepDepths`: 0 for a step fed only by `raw` (or with no flows), else 1 + the deepest step feeding it; flows that close a loop are ignored (depth-first with an "in progress" set).
- `unitsFromPlan`: steps that are `handCraft`, have `machine.mteId < 0`, or `count − owned ≤ 0` are skipped; a machine missing from `pack.machines` is skipped with `{ code: 'unknown_machine', stepId, text: '<name> (#<mteId>) is not in this recipe export' }`; a `steam` machine gets `electric: false` and `{ code: 'steam_machine', stepId, text: '<name> runs on steam: connect a steam supply by hand' }`. Units are sorted by (depth, step id, index); `tier = step.machine.tier`, `euPerTick = step.euPerTick`.
- A singleblock is `size [1, 1, 1]` with one `machine` cell (`machineRef(m)`, label `m.name`, item `m.itemKey`).
- A multiblock uses `structure` (Plan 1 canonical frame): the controller cell is `machine`, other cells with an `mteId` are `hatch` (named from `pack.machines`), the rest `casing` (label = item name of `itemKey(id, meta)`, else the block id; item = that key). Missing or `truncated` structure → a 3×3×3 box of `UNKNOWN_BLOCK` casings with the controller at `[1, 0, 0]` and warning `{ code: 'structure_unknown', stepId, text: '<name>: no exported structure, drawn as a 3×3×3 box — check its real size in game' }`.
- Hatch cells (they replace casings; gt-mechanics §5 — hatch positions are not in the export): bottom-layer candidates = `casing` cells at y = 0 holding the layer's most common `id@meta` (ties → smallest string). Front candidates = candidates with the smallest z of block cells in their column; back = the largest z. Front, ordered by `(|x − controller.x|, x)`: `input_bus` (if `io.itemIn`), `output_bus` (if `io.itemOut`). Back, ordered by `(|x − floor((W−1)/2)|, x)`: `energy` (if electric; tier = step tier), then `maintenance` (falls back to any remaining bottom candidate). Fluid hatches on the top layer (y = H − 1), candidates = that layer's most common casing, ordered by `(z, x)`: one `input_hatch` per `io.fluidIn` key, then one `output_hatch` per `io.fluidOut` key. Buses and fluid hatches are sized to the step (architecture §11.13): `input_bus` `pickHatch('MTEHatchInputBus', null, { slots: <distinct item input keys> })`, `output_bus` `{ slots: <distinct item output keys> }`, each `input_hatch`/`output_hatch` `{ litres: <that key's per-run amount> }`; a pick smaller than its need adds Task 3's `hatch_small` warning; energy `pickHatch('MTEHatchEnergy', tier)`. Every hatch cell records the casing it replaced in `replaces` (`itemKey(id, meta)` of that cell). Not enough cells or a missing hatch machine → `{ code: 'hatch_cells_short', stepId, text: '<name>: put the remaining hatches (<kinds>) on any casing' }`.
- Programmed circuit (architecture §11.14): `circuit = pack.recipeById.get(step.recipeId)?.meta.circuit`; when set, a singleblock's machine cell gets `config: { circuit }`, a multiblock's input bus cell gets it (a multiblock step with a circuit always gets an input bus, even without item inputs, because the circuit goes in the bus's circuit slot).
- `replacedCasings`: one line per `replaces` key over all units' hatch cells, `amount` = their count.
- `attachCovers`: returns the blocks in their order with each `HostCover.cover` appended to `covers` and each `HostConfig.config` merged key by key into `config` of the first block at that position whose role is not `ghost`; a position with no block throws `Error('no host block at <x>,<y>,<z>')` (a bug in the calling task, never user input). Blocks without covers or config keep neither field.
- `placeUnits`: cursors `cN = cS = headWidth`; each unit goes to row N when `cN ≤ cS`, else S; `x = cursor + (row not empty and (unit or the row's previous unit is a multiblock) ? 1 : 0)`; then, while any of its item-port spine cells is within `portSpacing − 1` of a cell already claimed (spacing 1: never the same cell; 2: never the same or a neighbouring cell), `x += 1`; cursor = `x + W`. `dN`/`dS` = deepest unit per row (0 when empty); `spineZ = 1 + dN`; `L = dN + dS + 3`; `tailX = max(cN, cS)`; `W = tailX + 1`; `H` = tallest unit. Row S units keep the canonical orientation (`at = [x, 0, spineZ + 1]`, cell `at + c`); row N units turn 180° (`at = [x, 0, spineZ − D]`, cell `at + (W−1−cx, cy, D−1−cz)`). Machine blocks face the spine (3 in row N, 2 in row S); bus hatches face the spine, energy and maintenance hatches face away, fluid hatches face up (1). Cell `config` is copied to the block. Air cells go to `reserved`.

Multiblock: `power` = the cell behind the energy hatch; `items` = the cells in front of the input/output buses when those are spine cells; fluid ports = the cells above the fluid hatches; `itemFaces` = the output bus's spine-facing side; `fluidFaces` = output hatches' tops.

  ```ts
  export function runX(supplyTier: number, tier: number): number;        // 2 × (supplyTier − tier)
  export interface FluidNet { key: StuffKey; name: string; litresPerSecond: number; producers: Vec3[]; consumers: Vec3[]; atTail: boolean;

    cables: Array<{ tier: number; cable: Machine; cells: number }>;      // tier descending
  ```

Rules (spec §3.5 never overvolt, §3.6 shared runs; gt-mechanics §3.3, §3.6):
- Runs: for the supply tier and every stage's `toTier`, a straight cable column at `x = runX(supply, tier)`, y = 0, z = 0 … L − 1. Run cable = `pickCable({ volts: V[tier], amps })` with `amps = supplyAmps` for the supply run and the stage's `ampsOut` below; `ampsShort` → `{ code: 'cable_amps', text: 'No cable carries <A> A at <TIER>: run <n> parallel <cable> lines' }` with `n = ceil(A / cable.amps)`.
- Banks: stage `from → to` puts `count` transformers (`pickTransformer(pack, to)`) at `x = runX(supply, to) − 1`, y = 0, z = `spineZ − floor(count/2) + j`, facing west (4): the front (step-down input) touches the higher run, the east face feeds the lower run. More transformers than `L` → the rest are left out with `{ code: 'transformer_bank', text: 'Put <n> more <name> beside the bank' }`; no transformer for that tier → `{ code: 'no_transformer', text: 'No <TIER> transformer in this export' }`.
- While one feed tier is routed, the power ports of units on other feed tiers are not passable (so a higher-tier run never takes a lower-tier machine's port cell).
- Each electric unit is fed from the run of `feedTier = min(unit.tier, supply)`; a unit above the supply tier gets `{ code: 'power_tier_low', stepId, text: '<names> need(s) <TIER> power but the line gets <SUPPLY>: it will run short — add a step-up transformer or a generator at <TIER>' }` (one warning per unit tier; under-voltage never damages a machine, gt-mechanics §3.5, so it is wired, not left out). For each feed tier (descending): `growTree(run cells, the units' power ports sorted by x, y, z, …)` with `passable` = inside `{min [0,0,0], max [W−1, H, L−1]}` (H = placement height, so runs may pass over singleblocks) and not occupied by placement blocks, `input.occupied`, reserved air cells, head blocks or earlier routed cells. Tree cells become `cable` blocks with the run's cable. Unreached → `{ code: 'route_failed', stepId, text: 'Could not wire <name> inside the line — connect it by hand' }`.
- Connections (`linkBits`): run cells link along z; tree links as returned; each port cell links to the block it powers; each transformer links to both runs. A cable never links to a run of another tier, so no machine ever receives more than `V[its tier]`.
- `fluidNets`: one net per fluid key in any placed unit's `io`; producers/consumers = units' `fluidOut`/`fluidIn` ports for that key; `atTail` when a plan flow of that key comes from `raw` or goes to `out`/`sink`, or touches a step with no placed unit; `litresPerSecond` = Σ `perSecond` of the flows of that key; `faces` = producers' `fluidFaces`, each with `rate` = Σ `perSecond` of that step's flows of the key ÷ the step's `count` (every machine of a step carries an equal share).
- Fluid trees (after power): root = `[tailX, tailFluidY + i, spineZ]` for the i-th `atTail` net (key order), else the first producer port (x, y, z order). `growTree([root], other ports)`; the root and new cells are `pipe` blocks (`pickFluidPipe(rate)`, label `<pipe name> (<fluid name>)`), port cells link down to their machine. Every face in `faces` gets a pump cover sized to its share (architecture §11.13–§11.14): `pick = pickPump(pack, face.rate, groupTier)`, one `HostCover { pos: face.pos, cover: { face: FACES[face.side], item: pick.key, settings: { mode: 'export', allowInput: false, rate: face.rate, unit: 'L/s' } } }` (covers sorted by pos, then face), plus `coverRateWarning('pump', pick, face.rate, groupTier, <unit name>, stepId)` when `pick.short` (once per step). No fluid pipe in the pack → `{ code: 'no_pipe', text: 'No GT fluid pipe in this export: connect <fluid> by hand' }`; unreached port → `route_failed` `'Could not lay the <fluid> pipe to <name> — connect it by hand'`.

- Spine links: along x; to each unit whose `ports.items` holds that cell; the tail column's cells to each other and to the chests beside them.

Rules:
- `choosePowerNetwork`: networks with `baseId === base.id` (all networks in `base.dim` when none match) that have taps; order: `voltageTier ≥ lineTier` first, then spare `generatorEUt.average − (loadEUt ?? 0)` descending, then id. `chooseLogisticsNetwork`: kinds by mode — `routed` → `routed`; `ae2` → `ae2`; `direct` → `routed`, else `ae2`, else an EnderIO item network (`kind 'enderio'` whose id does not start with `e:liquid:` — Plan 4 ids are `e:<conduit type>:…`; spec §3.6 mode 1 "hooked into whatever network exists", spec §6 EnderIO is common at the group's base); never `gtpipe` (a GT pipe network only carries what its sources push, and GT's one-item filter cover would not keep other base items out of the input chest, research §3.8); same base rule; within one kind, most `nodes` first, then id. `nearestTap`: smallest `manhattan` to `target`, ties by posKey. `choosePowerTap` (spec §3.5, §5 never overload a cable): `nearestTap` among taps with `freeAmps ≥ amps`; else among taps with `cableAmps ≥ amps` (the tap cable can carry the line; only generation is short, which the power fit reports); else `nearestTap` of all (that hookup stays a guide, below).
- `hookupPath`: starts = the tap's face neighbours that are passable; goals = the ports' face neighbours that are passable and not line cells. Passable = inside the voxel box, known, air or replaceable, not a line cell. Bounds = the voxel box ∩ (box around the tap and ports ± 16). `findPath(starts, goals, { maxNodes ?? MAX_PATH_NODES })`. Without voxels or when nothing is found: a straight guide `straightPath(s, g)` from the tap neighbour nearest to the nearest port to that port's neighbour nearest to the tap (ties in `DIRS` order), `found: false`.
- `powerHookup` (spec §3.5): cable = `pickCable({ volts: V[supplyTier], amps })`; none → `{ code: 'no_cable', text: 'No cable for <TIER> in this export' }`, no blocks (the guide path is kept). A tap whose own cable cannot carry the line — `tap.freeAmps < amps` and `(tap.cableAmps ?? tap.freeAmps) < amps` (Plan 4 caps `freeAmps` at the tap cable's rating) — is never wired: the path stays a dashed guide (`found` as computed, `blocks: []`, `parts: []`), warning `power_amps_low` (below) and `blocked = { cable: <blockName of the tap's voxel, else 'cable'>, amps }`, from which Task 10 writes the upgrade step; otherwise `blocked = null`. Every path cell is a `cable` block (`machineRef(cable)`, label and item from the cable); links between consecutive cells, the first cell toward the tap, the last toward the port it touches. `parts = [{ key: cable.itemKey, amount: path.length, why: 'power hookup', group: 'power' }]`; `lossEUt = lineLossEUt(amps, path.length, lossPerBlock)`; `arrivingVolts = V[supplyTier] − path.length × lossPerBlock`. Warnings: `path.length × lossPerBlock > LOSS_WARN_FRACTION × V` → `{ code: 'cable_loss_high', text: 'The power run loses <round(100 × len × loss / V)>% over <len> blocks of <cable> — move the line closer to the tap or use a better cable' }`; a blocked tap → `{ code: 'power_amps_low', text: 'The tap has <free> A free at <TIER>; the line draws up to <amps> A' }` (a tap whose cable carries enough but whose generation is short gets no amp warning — `fitPower` reports it); `ampsShort` → `cable_amps` as in Task 6; not found → `{ code: 'no_path', text: 'Could not find a free route for the power hookup — the dashed line is a straight guide; route it around obstacles' }` (logistics: "for the logistics hookup").
- `logisticsHookup`: every path cell is the `part` (`pr_junction`, `me_cable`, `eio_item_conduit` → role `pipe`); with `end`, the last cell becomes that part (`pr_interface` → `chip_pipe`, `me_export_bus` → `interface`) facing the port it touches; `endConfig` becomes the last cell's `config`. Parts counted per key, why `'logistics hookup'`, group `'logistics'`, sorted by key.
- `ghostBlocks`: one `ghost` block per position in `at` whose voxel is known and neither air nor replaceable and not in `exclude`; label `existing <blockName>` (spec §3.8: existing base blocks only as faint ghosts where the line connects).

`layoutLine` stages (see "How a layout is built"):
1. `mode = project.settings.logistics`; `parts = resolveParts(pack)`. A plan whose `status` is `empty` or `infeasible` → `{ status: 'empty', dim: 0, origin: DEFAULT_ORIGIN, size: [0, 0, 0], rotation: 0, mode, blocks: [], hookups: [], pins: [], buildSteps: [], bom: [], warnings: [] }` (the plan already says why).
2. `base = findBase(scan, project.world.baseId)`. No base → `status 'no-world'`, origin `DEFAULT_ORIGIN`, rotation 0, no pins, no hookups, warning `{ code: 'no_scan', text: 'Pick a world scan and base on the Map tab to place the line' }` when `project.world.scanId` is null, else `{ code: 'no_base', text: 'This scan has no base here to build next to' }`; everything local (units, mode, internal routing, steps without pins) is still built so the 3D view and the parts list work, stages 6, 8 and 9 are skipped (except stage 8's AE2 idle adjustment), and `power` = `plan.power` plus that idle draw (nothing to compare against, so `fits` stays unset). `ctx = base ? contextFromScan(scan, pack, base.id) : emptyContext()`.
3. Units (Task 5). None → `status 'empty'` with reuse pins and reuse steps only (and `power` from step 8 with no extra loss).
4. Power: `lineTier` = highest electric unit tier; `network = choosePowerNetwork(scan, base, lineTier)`; `supplyTier = network?.voltageTier ?? lineTier`; `stages = transformerStages(tierGroups(electric units), supplyTier)` (null when no electric unit). Logistics network = `chooseLogisticsNetwork(scan, base, mode)`.
5. `placeUnits(units, { headWidth: headWidthFor(stages), portSpacing: PORT_SPACING[mode] })` → `buildMode` → `routeInternal({ …, occupied: [...placement.blocks, ...mode.blocks], fluids: fluidNets(…), tailFluidY, groupTier: plan.tier })`; local blocks = `attachCovers([...placement.blocks, ...mode.blocks, ...internal.blocks], [...mode.covers, ...internal.covers], mode.configs)` — no block has role `cover`. Local size = `[W, 1 + highest block y, L]`. `replaced = replacedCasings(units)` (set on the layout when not empty, also for `no-world`).
6. Site (Task 4): `avoid` = posKeys of every scanned machine, pipe, storage block and `logisticsBlocks` entry in the base's dimension; `ports.power = [−1, 0, spineZ]` (when there is a power head), `ports.logistics` = the logistics port's first face neighbour outside the box (`DIRS` order); taps for scoring = the network taps nearest the base centre; `vox = await deps.readArea?.(base.dim, siteSearchBox(…))` (a thrown `RangeError` or missing `readArea` → `vox = null` and `{ code: 'terrain_unknown', text: 'The ground around the base could not be read; the line is placed beside the base unchecked' }`). With `project.placement`: `checkPlacement`; `blocked > 0` → `{ code: 'placement_blocked', text: '<n> block(s) are/is in the way at the chosen spot' }`, `moved` → `{ code: 'placement_moved', text: 'Moved the line to y=<y> to stay inside the world height' }`. Without: `findSite` ?? (`fallbackSite` + `{ code: 'site_not_clear', text: 'No clear, flat ground near the base: the line is placed beside it — <blocked> blocks in the way, <unsupported> columns without a floor' }`).
7. Every local block goes to the world with `toWorld`, `rotateFacing`, `rotateConnections`, and every `covers[].face` with `rotateFace` (the cover turns with its block; `config` is copied unchanged); world size = `rotatedSize`.
8. Hookups (Task 9, only with a base): power when `network` and electric units exist (tap = `choosePowerTap(network.taps, world power port, stages.supplyAmps)`; ports = the supply run's world cells; `amps = stages.supplyAmps`; a `blocked` result becomes `StepsInput.power.upgrade`); logistics when the mode returned a `hookup` and a network exists (ports = `[world logistics port]`, `endConfig` passed through). Hookup blocks get `hookup` = their index; `ghostBlocks(vox, pack, [tap.pos], lineCells)` per hookup. No power network but electric units → `{ code: 'no_power_tap', text: 'No power network found at this base' }`. AE2 idle draw (architecture §11.13): `idle = ae2IdleEUt(all line and hookup blocks, parts)`; the power used below is `plan.power`, or when `idle > 0` `{ ...plan.power, averageEUt: averageEUt + idle, peakEUt: peakEUt + idle }`. Then `fitPower({ power, ctx, extraLossEUt: stages.lossEUt + power hookup lossEUt, pack, tier: supplyTier })`; when `idle > 0` its `detail` gains `'; AE2 parts idle: <fmtRate(idle)> EU/t'`. Without a base (stage 2) the same idle-adjusted `power` is the layout's `power`.
9. Pins (Task 10): site centre `[origin.x + floor(W'/2), origin.y, origin.z + floor(L'/2)]`; warnings with a place — `site_not_clear`, `placement_blocked`, `no_power_tap`, `routed_missing`, `ae2_missing` at the site centre, `no_path` at its hookup's first path cell. Reuse finds near the site centre.
10. Steps (`layoutSteps` with `blocks` = all world blocks, `origin`, `nameOf = (k) => plan.names?.[k] ?? pack.nameOf(k)`), parts (`bomFromBlocks(all blocks, [...mode.extraParts, ...fit.optional])` — every line grouped), and one `{ code: 'part_unknown', key, text: '<name> is not in this recipe export; check the part in game' }` per used part that `resolveParts` did not find and per `covers[].item` missing from `pack.items`.
11. Warnings = units, mode, internal, site, hookup warnings in that order, de-duplicated by `code + text`. Blocks sorted by x, y, z, role, facing. `status 'ok'`, `power = fit.power`.

`mergeLayoutIntoPlan` (the server-side join used by the `planFinish` hook, Task 12): a plan whose `status` is not `ok` is returned unchanged. Otherwise `power = layout.power ?? plan.power`; `buildList` = `mergeBom(subtractReplaced(plan.buildList, layout.replaced ?? []), expanded?.lines ?? required)` followed by the optional lines (why starting `optional:`) — merged into an existing line of the same key, else appended — so `buildTotals = mergeBom(plan.buildTotals ?? [], expanded?.totals ?? [])` never counts generator suggestions; every line keeps its `group` (architecture §11.13: `mergeBom` keeps the first non-empty group per key; lines from `expandBomLines` keep theirs), so the client can show Machines / Power / Piping & logistics / One-off. `subtractReplaced` (Plan 2's `buildBom` lists every exported structure casing under `structure of <n>× <name>`, but hatches stand on some of those cells): each line whose key is a `replaced` key loses that amount (never below 0; a line reaching 0 is dropped; its `children` amounts scale by `ceil(child × new / old)`); `buildTotals` keep the slightly higher base-material count; `buildSteps = mergeBuildSteps(…)`; warnings = plan warnings + layout warnings not already present (code + text); `names` gains `nameOf(key)` for every new key. `mergeBuildSteps`: when the layout has steps, keep the plan's `gather` and `craft` steps, then the layout steps, then the plan's `configure`, `handcraft` and `test` steps (dropping the generic `place`, `power` and `logistics` steps), renumbering `order` from 1; with no layout steps the plan's steps are returned as they are.

```ts
export const VERTEX_SHADER = `
attribute vec3 aTiles0; attribute vec3 aTiles1; attribute float aLayer;
varying vec2 vUv; flat varying float vTile; varying float vShade; varying float vLayer;
void main() {
  vec3 n = normalize(mat3(instanceMatrix) * normal);
  if (n.y < -0.5) { vTile = aTiles0.x; vShade = 0.5; } else if (n.y > 0.5) { vTile = aTiles0.y; vShade = 1.0; }
  else if (n.z < -0.5) { vTile = aTiles0.z; vShade = 0.8; } else if (n.z > 0.5) { vTile = aTiles1.x; vShade = 0.8; }
  else if (n.x < -0.5) { vTile = aTiles1.y; vShade = 0.6; } else { vTile = aTiles1.z; vShade = 0.6; }
  vUv = uv; vLayer = aLayer;
  gl_Position = projectionMatrix * modelViewMatrix * instanceMatrix * vec4(position, 1.0);
}`;
export const FRAGMENT_SHADER = `
precision highp sampler2DArray;
uniform sampler2DArray uTex; uniform float uMaxLayer; uniform float uAlpha;
varying vec2 vUv; flat varying float vTile; varying float vShade; varying float vLayer;
void main() {
  if (vLayer > uMaxLayer + 0.5) discard;
  vec4 c = texture(uTex, vec3(vUv.x, 1.0 - vUv.y, vTile));
  if (c.a < 0.1) discard;
  gl_FragColor = vec4(c.rgb * vShade, uAlpha);
}`;
```
