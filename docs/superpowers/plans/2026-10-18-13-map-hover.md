# Map Hover Info Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Hovering any block on the world map shows what it is: the block's name and position and, where the scan found something there, the machine, cable, pipe, storage or logistics details.

**Architecture:** The client already holds the scan (`WorldScan`) and the map tiles (palette index + height per column). A pure module builds a column index of scan records; the server's palette route can return English names for each palette entry; `MapView` shows a small tooltip on pointer move. Overlays (Plan 5's planned line, later the EnderIO lane) contribute their own lines through an optional `describe` hook on `MapOverlay`.

**Tech Stack:** React 19 client (`src/client/map/*`, `src/client/views/MapView.tsx`, `MapTab.tsx`), server route `src/server/http/routes/world.ts`, pack lookups (`Pack.items`, `Pack.machines`, `Pack.nameOf`), vitest (SSR, node env), Playwright.

**Spec:** `docs/superpowers/specs/2026-10-17-gtnh-planner-design.md` §3.7 (map view; "hover a block for its name" is the user's request of 2026-10-18), architecture §7.2 (`MapOverlay`, `MapViewport`, `MapMarker`) and §11.11.

## Global Constraints

- Tooltip appears ≤ 150 ms after the pointer rests on a column, follows the pointer, hides on leave, never covers the hovered block (offset 12 px), and is keyboard/screen-reader friendly (`role="tooltip"`, the map canvas has `aria-describedby` while it shows).
- Lines, in this order: (1) block name in English (palette entry → `Pack.items` name of `<id>@<meta>`, else of `<id>@0`, else for `gregtech:gt.blockmachines` the `Pack.machines.get(mteId).name`, else the registry name), (2) `x y z` of the block (y = the top block at the current Y limit), (3) the scan record at that column if any, top-most first: GT machine → `name (TIER)` + `facing <dir>` + `stored <EU> EU` when known; GT cable/pipe → material, voltage tier and amps (cables) or capacity (pipes); storage → kind + up to 3 largest contents `<count>× <name>` + `+N more`; routed pipe / EnderIO conduit / AE2 part → type and connected sides; (4) the base name if the column lies inside a base, (5) lines from every overlay's `describe(x, z)`.
- `MapOverlay` gains optional `describe?(x: number, z: number): string[] | null` (append-only contract change; record it as a new entry at the end of `docs/superpowers/plans/2026-10-17-00-architecture.md` §11).
- `GET /api/world/scans/:id/palette?names=1` returns `Array<{ block: BlockRef; name: string }>` (same order as the plain palette); without `names` it stays exactly as today.
- No new dependencies. Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. A column with no scan record shows only the block name and position (no empty lines).
2. GT machine blocks name the machine (e.g. "Assembling Machine (MV)"), not "gregtech:gt.blockmachines".
3. Storage with hundreds of item kinds shows at most 3 plus "+N more".
4. Hovering over the planned-line overlay (when an overlay supplies `describe`) shows its lines last.
5. Moving the pointer fast across the map never queues stale tooltips (only the latest column is described).
