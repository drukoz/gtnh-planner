## Architecture change requests

One entry, appended by Task 1 to `docs/superpowers/plans/2026-10-17-00-architecture.md` §11 as number **43** (its (a) with the controller's block-id rule, ruling P3; see "As built"):

> 43. **Missing textures** (spec §3.8, added 2026-10-19 after the user's reports; plan `2026-10-19-16-textures.md`). (a) Resolver order — block faces: GT dump block table (a meta whose six faces are all empty after dropped layers counts as absent) → GT ore block → GT material block (frames, sheetmetal, storage blocks from the pack's `gt {prefix, material}`) → curated table → the dump's texture name (exact, then face-aware suffix probing) → the file-name rule (`src/server/assets/names.ts`) → none. Icons: NEI → for fluids: GT still → the fluid block's texture (0.4.0 `fluids[].block`) → fluid file by name → GT `fluid.autogenerated` tinted → none; for items: GT meta item → GT material template (metaitem.98/99, BartWorks) → curated item table → item texture name (exact, then probing) → file-name rule (items atlas, numbered `<name>/<meta>` first; skipped for a block id) → block faces → fallback. A rule only ever picks a square file or an animation strip; items look in `items/` before `blocks/`; in `items/` a registry name never loses a trailing `Block` or `_block` (only `Item` or `_item`), so a block's item never takes its material's item icon; a block id — an id the dump's `blockIds` lists, which includes every ItemBlock — never takes an `items/` file through the file-name rule, in its own domain or any other: block ids use only the `blocks/` rules, their item texture name and the curated rows; a basename or case-insensitive match counts only when it is the only one; the block and item name rules also run without a dump (the mod id as the only domain, and no id counts as a block id), the fluid rules only with one. (b) `TextureLayer.region?: LayerRegion` = `{ sheet: number; src: [x, y, w, h]; dst?: [x, y, w, h] }`: `src` in pixels of a sheet `sheet` pixels wide (scaled to the file's real width), `dst` in sixteenths of the tile (default the whole tile); clients crop `src`, draw it at `dst`, and key every image cache by path and region. (c) `BlockFaces.pipe?: PipeLayers` = `{ core; arm; end: TextureLayer[] }` for blocks drawn as a core with arms: the 3D view draws the core with `core`, an arm's tip with `end` and its long faces with `arm` (u along the arm), every textured pipe tile over its block role's plain colour; curated pipes carry crops of their model sheets, GT pipes their unconnected side (exported or derived). (d) Animated textures have square frames: `frames = floor(h / w)`, as Minecraft 1.7.10 cuts them. (e) The extractor also copies `minecraft/textures/entity/chest/*.png` and `ironchest/textures/model/*.png`. (f) `POST /api/pack/names` `{ keys: StuffKey[] }` (at most `ASSET_KEYS_MAX`) → `Array<string | null>` in request order. (g) `textures.json.gz` from exporter 0.4.0 (format unchanged, every field optional): `mte[].unconnected`, `fluids[].block`, `prefixTextures`, `fluids[].still` following `iconsFrom` first, `metaItems` rows for the Programmed Circuit and GGFab's `gt.ggfab.d1`, `blocks` rows for GT storage, frame and sheetmetal blocks. (h) Icons scale evenly: an upscale that is not a whole multiple goes nearest-neighbour to the next whole multiple, then smooth to the target; a downscale is smooth. A region crop is scaled nearest-neighbour to its place in the tile. (i) Optional: `AppConfig.clientInstance` and `AppConfig.useResourcePacks` (default `false`) overlay the client instance's enabled resource packs on the jar textures, `options.txt` order, last wins. (j) `orientFaces(faces, facing)`: a block facing up or down whose four sides share their first layer keeps every world side's own canonical layers (BOTTOM, TOP, SIDE hulls with their overlays), except that the facing side draws its own hull under the front's (canonical north's) overlays and world north draws its hull alone, as `MTEBasicMachine.getTexture` does with a vertical main facing; every other block turns whole (`rotateFaces`).

The rules, exactly as measured in "Background":

- `stemsOf(n, atlas)`: `[n]`, then `n` without a leading `item.` / `tile.` / `block.` (any case), then its last `.`-separated segment, then each of those (in that order) without a trailing `Block`, `_block`, `Item` or `_item` — for the `items` atlas only without a trailing `Item` or `_item`; empty and repeated stems dropped. (In `items/` the un-suffixed `Block` stem is the block's material: `minecraft:diamond_block` → `items/diamond.png`, Botania `petalBlock` → `items/petal.png`; see "Background".)
- `stemCandidates(s, meta, face)`: `` `${s}/${meta}` `` (numbered folder, RC2); for `meta > 0` `` `${s}_${meta}` ``, `` `${s}.${meta}` ``; `s`; for `meta === 0` `` `${s}_0` ``, `` `${s}.0` ``; the face suffixes — up `_top`; down `_bottom`, `_top`; north `_front`, `_side`; south `_back`, `_side`; west and east `_side`; then `_normal`, `_0` (only for `meta > 0`), `_stage_0`.
- `modDomains(dump, mod)`: `mod.toLowerCase()`, then every other domain the mod's own `textureNames` (items and blocks) use, most used first, ties by name; a texture name without `:` counts as `minecraft`.
- `fileByName`: the stems are `stemsOf(registryName, atlas)`; for each stem, each domain, each candidate: `names.file(`${domain}/textures/${atlas}/${candidate}.png`)`; then for each stem, each domain: `names.unique(`${domain}/textures/${atlas}/`, `${stem}.png`)`; first hit wins.
- `facesByName` / `textureNameFaces`: each face by itself (`fileByName` with that face, or `textureNameFile` on the texture name's own root and stem); a face that finds nothing takes the first face, in `FACES` order, that did; null when none did. `textureNameFile(names, iconName, atlas, meta, face)` splits `iconPath(iconName, atlas)` into its folder and stem and tries `stemCandidates` there.

### Task 11 (optional, only after the user says yes): the client's resource packs as an overlay

The NEI icons are renders from the user's client, so they carry its resource packs (Modernity-GTNH); the jar textures do not, so block faces in the 3D view and the Map's colours can look unlike the game. With `useResourcePacks` on, `extract-assets` also reads the client instance's enabled resource packs and lets them win over the jars, as the game does: Minecraft 1.7.10 writes the enabled packs to `options.txt` as `resourcePacks:[…]`, bottom of the in-game list first, and `FallbackResourceManager.getResource` asks the packs from the last one down — the last listed wins, and every user pack wins over the mod jars and vanilla. Measured on the user's instance `GT_New_Horizons_2.9.0-RC-1_Java_17-26` (read-only, `w16/packs.py`): `resourcePacks:["UU-Tex-main","Modernity-GTNH-Dark-UI","Modernity-GTNH-2026-08-31.zip"]` — two folders and a zip, no symbolic links — holding 34,230 block, item and chest-sheet PNG paths (Modernity wins 31,232, UU-Tex 2,959, Dark UI 39); 21,672 of them replace a file extracted today, 12,558 are new. Licences: resource packs carry their own (research §7, "Client resource packs … Same rule if a dump captures them"), so they follow the rule every jar texture follows: read from the user's own instance, copied only into the git-ignored `data/assets/`, served only behind the password, never committed.

**Files:**
- Create: `src/server/assets/resource-packs.ts`, `tests/unit/assets/resource-packs.test.ts`
- Modify: `src/server/config.ts` (`clientInstance`, `useResourcePacks`), `src/server/assets/index.ts:11-16` (`AssetConflict['rule']`, `sources[].kind`), `src/server/assets/extract.ts` (packs as sources: folder scan and copy, `pickWinner`), `src/server/cli/extract-assets.ts`, `README.md` ("Textures and icons"), `docs/research/textures-icons.md` (§7 policy, item 4)
- Test: `tests/unit/server/config.test.ts`, `tests/unit/assets/extract.test.ts`, `tests/unit/cli/extract-assets.test.ts`

**Interfaces:**
- Consumes: `textureEntry`, `pngSize`, `animationFrames`, `extractAssets`' passes; `loadConfig`.
- Produces:
  - `AppConfig.clientInstance?: string | null` (the instance's game folder, the one holding `options.txt` and `resourcepacks/`; default `null`), `AppConfig.useResourcePacks?: boolean` (default `false`); `loadConfig` refuses other types with a `ConfigError` naming the field.
  - `resource-packs.ts`: `interface ResourcePack { name: string; path: string; format: 'zip' | 'folder' }`; `parseResourcePacks(optionsTxt: string): string[]` (the `resourcePacks:` line's JSON array, its strings in order; `[]` when the line is missing or not a JSON array); `enabledPacks(instanceDir: string): Promise<{ packs: ResourcePack[]; missing: string[] }>` (each name resolved in `<instanceDir>/resourcepacks/`: a file → zip, a folder → folder; a name with `/`, `\`, a control character, or equal to `.` or `..`, and a name that is neither, go to `missing`); `scanFolder(dir: string): Promise<Map<string, { crc: number; size: number; file: string }>>` (every regular file below `<dir>/assets/` whose `assets/…` name `textureEntry` accepts, keyed by that result; symbolic links skipped).
  - `extract.ts`: `JarSource.kind: 'client' | 'mod' | 'pack'`, `JarSource.order?: number` (a pack's place in `options.txt`, the higher wins); `AssetConflict['rule']` adds `'pack-over-jar' | 'last-pack'`; `AssetIndexFile.sources[].kind` adds `'pack'`.

`pickWinner` gains two steps before today's: (0) `'pack-over-jar'` — packs beat every jar; (0b) `'last-pack'` — among two or more packs the highest `order` wins. Packs are scanned after the jars, in `order`, so `index.json` lists them last. Folder packs are scanned with `scanFolder` (reading each file once for its CRC) and copied with `readFile`; a zip pack takes the jar path. A pack that cannot be read is skipped like a jar (`skippedJars`); packs never count as mod jars for the "no mod jar could be read" check. The CLI, when `useResourcePacks` is `true`: no `clientInstance` → exit 2, `useResourcePacks is on: set "clientInstance" in data/config.json to the client instance's game folder (the one holding options.txt)`; no `options.txt` there → exit 2, `No options.txt in <folder>`; otherwise one line `Resource packs, last wins: <names>`, one `warning: resource pack <name> is enabled in options.txt but not in resourcepacks/, skipped` per missing name, and `WINNER_RULE` reads `winner: a resource pack over every jar (the last enabled first), then mod over vanilla, then an overriding jar over the texture's own mod, then the last jar by name`. When it is `false` nothing changes.
