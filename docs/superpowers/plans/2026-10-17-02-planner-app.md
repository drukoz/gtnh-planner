# Planner App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the web app the group uses to plan a production line: password-protected server, shared live-synced projects, a least-raw-material planner (HiGHS LP) limited to the group's tier and reachable dimensions, and the flow diagram, materials, steps and notes views.

**Architecture:** A `node:http` server (TypeScript run directly by Node 24) serves a Vite/React client, a JSON API and one SSE stream per open project; projects live in `node:sqlite` and change only through `ProjectOp`s applied by the shared pure `applyOp` on both sides. The planner (`src/server/planner/*`) builds candidate recipes from Plan 1's `Pack`, computes which base materials are reachable, prices goods in ingot-equivalents, solves a lexicographic LP (raw cost, then power, then a canonical form) and turns the result into steps, machines with GT overclocking, a build list and build steps; `planLine` results are cached by settings hash + export id + scan id + base id (`planForProject`), and the plan route applies an optional `app.services.planFinish` hook (Plan 5). World data arrives later through the `app.services.planContext` hook (Plan 4); this plan works with `emptyContext()`.

**Tech Stack:** Node 24 (type stripping) · TypeScript 6.0.3 · `node:http` · `node:sqlite` · `node:crypto` (scrypt, HMAC) · highs 1.15.3 · React 19.3.0 · Vite 8.3.2 · elkjs 0.12.0 (Web Worker) · vitest 5.0.3 · @playwright/test 1.63.0

**Spec:** `docs/superpowers/specs/2026-10-17-gtnh-planner-design.md` (§3.2, §3.3, §3.3b, §3.9, §3.10, §3.11, §5). Contracts: `docs/superpowers/plans/2026-10-17-00-architecture.md` (authoritative: §2–§10). Facts: `docs/research/prior-art.md` §3, `docs/research/gt-mechanics.md` §1–§2, §6 and its independent-review appendix, `docs/research/materials-availability.md` §5, §8, `docs/research/web-stack.md`, `docs/research/export-mod.md` §2.

## Global Constraints

- Node `>=24.10.0 <25`; server entry `node --disable-warning=ExperimentalWarning src/server/main.ts`.
- TypeScript erasable syntax only: no `enum`, `namespace`, parameter properties, decorators or `<T>x` casts; enums are `as const` objects; relative imports name the real `.ts`/`.tsx` file; type-only imports use `import type`.
- npm dependencies used here, all pinned by architecture §4: typescript 6.0.3, @types/node 24.19.1, vite 8.3.2, @vitejs/plugin-react 6.1.1, react 19.3.0, react-dom 19.3.0, @types/react 19.3.0, @types/react-dom 19.3.0, elkjs 0.12.0, highs 1.15.3, vitest 5.0.3, @playwright/test 1.63.0 — no other package (client tests render with `react-dom/server`, no DOM library). Install missing ones with `npm install --save-exact --before="$(date -v-14d +%F)" <pkg>@<ver>` and commit `package-lock.json`.
- `src/shared/` is pure TypeScript for both sides: no `node:*` imports, no DOM.
- Units: rates are per second internally (`perSecond`), shown per minute or per hour in the UI; items in items, fluids in litres; energy EU/t; time in ticks (20 t = 1 s).
- Tiers 0..14 = ULV, LV, MV, HV, EV, IV, LuV, ZPM, UV, UHV, UEV, UIV, UMV, UXV, MAX; `V[t] = 8·4^t` (t ≤ 13), `V[14] = 2147483640`.
- Material cost (spec §3.3, architecture §5): every base item counts 1; GT material forms cost `costPerIngot(material) × prefixAmount / 3628800`; molten fluid `costPerIngot × L / 144`; any other fluid 1 per 1,000 L; water, air, cobblestone and lava are free; every cost can be overridden per project by material name or by key.
- Objective (spec §3.3): least raw material consumed while the line runs at the current tier. Machine count, power and speed are shown, never optimized (power is only a tie-break).
- Anti-goals (spec §5): never plan what the group cannot run at its tier (recipe voltage per amp above the machine tier, or a machine tier above the group tier, is never chosen); never treat an unreachable base material as buyable; never lose shared project state.
- Config `data/config.json` (another file only through env `GTNH_PLANNER_CONFIG`, architecture §11.1): `port` 8765, `host` `'0.0.0.0'`, `dataDir` `'data'`; session cookie `gp_session` (HMAC, 30 days); the password is stored only as a scrypt hash.
- SSE: `retry: 2000`, heartbeat comment `: hb` every 20 s, events `snapshot`, `op`, `plan`.
- Never start, stop or write to the live Minecraft server or its folder. This plan never reads the world at all.
- Nothing game-derived or private is committed: tests build synthetic packs and exports with `tests/helpers/`; real-data checks run only with `GTNH_LOCAL=1`. `data/` holds the DB, config and exports and is gitignored.
- Commits use a conventional prefix and the message ends with the line `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Several people editing one project at once, or a laptop waking from sleep with a stale tab:** every tick, note and setting survives; all open tabs converge on the same project; a missed op is recovered by refetching, never by guessing. Tests: Task 6 "applies concurrent batches in arrival order without losing any"; Task 15 "applies other people's ops on top of my pending ones" and "refetches the project after a missed op"; Task 19 sync spec (tick seen by the other person, still there after reload).
2. **A friend whose name has non-ASCII characters (é, ü, emoji):** ticks and notes show the name exactly as typed. Tests: Task 6 "keeps non-ASCII names exactly"; Task 19 sync spec (`Jörg 🙂`).
3. **A target the group cannot make yet** (nothing at their tier makes it, or its only raw material needs an unreachable planet): the plan says so in plain words and names what unlocks it, instead of an empty page or an error. Tests: Task 10 "reports what blocks an impossible target"; Task 14 "explains what blocks a target in plain words"; Task 19 "an impossible target explains what unlocks it".
4. **Free-input and loop routes** (lava centrifuging into metal, item cycles that look free): never a plan that makes something from nothing, while legitimately free inputs (water electrolysis) still plan normally. Tests: Task 7 "excludes lava centrifuging unless the group turns the rule off"; Task 10 "never makes something from nothing" and "free inputs are still inputs".
5. **The pack re-exported under an existing project** (2.9.0 final replaces RC-1, recipe ids change): pinned recipe choices that no longer exist are dropped with a warning and the project still plans. Tests: Task 7 "honours a pinned recipe and warns about a stale pin"; Task 14 "drops a stale pin with a warning and still plans".

**Interfaces:**
- Consumes (Plan 1): `StuffKey`, `ItemKey` from `src/shared/keys.ts`; `Product` from `src/shared/types/pack.ts`.
- Produces:
  - `src/shared/types/plan.ts`: every name of architecture §6.3, verbatim, plus these optional additions (allowed by architecture §6 "may add optional fields"):
    - `export type LeafClass = 'free' | 'direct' | 'byproduct' | 'derived' | 'natural' | 'stop' | 'unavailable'`
    - `RawInput.leafClass?: LeafClass`
    - `PlanStep.mainOutput?: StuffKey` (the good this step was chosen to make; key used for `recipeChoice`), `PlanStep.oc?: { recipeEuPerTick: number; recipeDurationTicks: number; machineVoltage: number; machineAmps: number; perfect: boolean; heatOverclocks: number }`, `PlanStep.needsCleanroom?: boolean`, `PlanStep.runs?: number` (whole runs in Make N), `PlanStep.circuit?: number` (the programmed-circuit configuration the recipe needs, spec §3.6; Task 11)
    - `BomLine.children?: BomLine[]` (one level of breakdown; leaves have none)
    - `BomLine.group?: 'machines' | 'power' | 'logistics' | 'one-off'` (architecture §11.13; the "to build" list is shown in these groups, a missing group counts as `machines`)
    - `PlanSettings.declineReuse?: number[]` — mteIds of owned machine types the group does not want to reuse for this line (spec §3.3 "suggests reusing them. The group decides."). Optional in the type because architecture §6 allows only optional additions; `defaultSettings()` and `normalizeSettings()` always fill it, and readers use `settings.declineReuse ?? []`.
    - `Plan.status?: 'ok' | 'empty' | 'infeasible'`, `Plan.buildTotals?: BomLine[]` (base materials of the whole build list, summed), `Plan.names?: Record<string, string>` (English name of every key used in the plan, plus `dim:<DimensionInfo.key>` → dimension name, so the client never needs the pack)
    - `export const DEFAULT_EXCLUDED_CATEGORIES: readonly string[] = ['recycling', 'massfab', 'replicator', 'scrap', 'lava-centrifuge']`
    - `export const FREE_KEYS: readonly StuffKey[] = ['fluid:water', 'fluid:lava', 'fluid:air', 'minecraft:cobblestone@0']` (Nether Air and Toxic Air are not free: they are dimension-gated fluids that come from `worldgen.fluidSources`, materials-availability §2.3)
  - `src/shared/types/project.ts`: `Note`, `Mark`, `Project`, `ProjectOp` exactly as architecture §6.4.
  - `src/shared/project/apply-op.ts`:
    - `applyOp(p: Project, op: ProjectOp, by: string, at: string): Project` — pure, never mutates `p`, returns a new object with `rev + 1`.
    - `defaultSettings(): PlanSettings`
    - `normalizeSettings(s: Partial<PlanSettings> | undefined): PlanSettings` — `{ ...defaultSettings(), ...s }` with `dims` filled field by field (old projects keep working when later plans add settings).
    - `validateOp(op: unknown): string | null` — `null` when valid, else a short English reason (used by the ops route for 400s and by the client before sending).
    - `export const MAX_NOTE_LENGTH = 4000`, `export const MAX_NAME_LENGTH = 80`.

Op semantics (decided here): `settings` replaces exactly the fields present in `patch` (records and arrays are replaced whole; the client always sends the full new value computed from its latest state). `mark` with `on: true` sets `marks[row] = { by, at }`, `on: false` deletes it. `addNote` with an `id` that already exists replaces that note's text and pin (so a retried request never duplicates a note); `editNote`/`deleteNote` on an unknown id change nothing but `rev`. `world` sets both ids; `placement` sets `{origin, rotation}`; `clearPlacement` sets `null`. `rename` trims.

`defaultSettings()` returns exactly: `{ target: null, mode: 'rate', amount: 1, per: 'min', tier: null, dims: { policy: 'progression', overrides: {} }, routeDerived: false, logistics: 'direct', costOverrides: {}, stopItems: [], expandItems: [], recipeChoice: {}, machineTier: {}, excludedCategories: [...DEFAULT_EXCLUDED_CATEGORIES], coilHeat: null, automateCrafting: false, declineReuse: [] }`.

`validateOp` rules: `rename.name` trimmed length 1..80; `settings.patch` has only `PlanSettings` keys; `amount` finite, `> 0`, `≤ 1e9`, and an integer when the resulting mode is `makeN` (check the patch's own `mode` if present, else accept any positive amount — `ProjectStore.apply` re-checks against the resulting settings, Task 4); `tier` `null` or integer 0..14; `per` `'min' | 'hour'`; `mode` `'rate' | 'makeN'`; `logistics` one of `LogisticsMode`; `costOverrides` values finite `≥ 0`; `machineTier` values integers 0..14; `coilHeat` `null` or integer 0..100000; `dims.policy` `'progression' | 'visited'`, override values `'on' | 'off'`; list fields are arrays of strings, except `declineReuse`, an array of integers; `mark.row` matches `/^(build|run|step):.{1,300}$/`; note `text` length 1..4000, `id` 1..64 chars, pin coordinates finite integers; `world` ids `string | null` up to 100 chars; `placement.rotation` in `0 | 90 | 180 | 270`.

### Task 2: GT overclock calculator port

**Files:**
- Create: `src/shared/gt/overclock.ts`
- Test: `tests/unit/shared/overclock.test.ts`

**Interfaces:**
- Consumes (Plan 1): `V` from `src/shared/gt/tiers.ts`.
- Produces (`src/shared/gt/overclock.ts`, pure, shared by server and client):
  - `export const VP: readonly number[]` — `VP[t] = floor(V[t] × 30 / 32)`, t = 0..14 (`[7, 30, 120, 480, 1920, 7680, 30720, 122880, 491520, 1966080, 7864320, 31457280, 125829120, 503316480, 2013265912]`).
  - `export function log4(a: number): number` (floor; 0 for a ≤ 1) and `log4ceil(a: number): number` (smallest n with 4ⁿ ≥ a; 0 for a ≤ 1). Integer loops, no `Math.log` (values reach 2.3·10¹⁵).
  - `export function powInt(base: number, exp: number): number` — exponentiation by squaring, as `GTUtility.powInt`.
  - `export function voltageTier(v: number): number` — `GTUtility.getTier`: smallest t with `V[t] ≥ v`; 0 for v ≤ 8; 15 above `V[14]`.
  - `export interface OcInput { recipeEUt: number; duration: number; machineVoltage: number; amperage?: number /*1*/; parallel?: number /*1*/; currentParallel?: number; amperageOC?: boolean /*false*/; perfectOC?: boolean; eutIncreasePerOC?: number /*4*/; durationDecreasePerOC?: number /*2, or 4 when perfectOC*/; durationModifier?: number /*1*/; eutDiscount?: number /*1*/; heatOC?: boolean; heatDiscount?: boolean; recipeHeat?: number; machineHeat?: number; maxOverclocks?: number /*Infinity*/; noOverclock?: boolean }`
  - `export interface OcResult { euPerTick: number; durationTicks: number; overclocks: number; heatOverclocks: number }`
  - `export function calculateOverclock(input: OcInput): OcResult` — the non-laser path of `OverclockCalculator.calculateOverclock`, exactly the pseudo-code in gt-mechanics §2.5 (heat OC threshold 1800 K, heat discount 0.95 per full 900 K, 32 EU/t floor when counting OCs, voltage-tier cap only when `amperageOC` is false, integer division where Java uses `long`/`int`, duration floored and at least 1 tick, no stop at 1 tick).
  - `export function multiplierUnderOneTick(input: OcInput): number` — 1 when the unfloored overclocked duration is ≥ 1 tick, else `ceil(1 / unflooredDuration)` (gt-mechanics §2.3; used only for multiblock parallels).
  - `export interface MachineOc extends OcResult { machineVoltage: number; machineAmps: number; parallel: number }`
  - `export function singleblockOverclock(recipe: { euPerTick: number; durationTicks: number }, machine: { tier: number; amps: number }): MachineOc` — `machineVoltage = V[tier] × amps`, `amperage 1`, `amperageOC false`; `amps === 3` (arc furnaces, the only 3 A singleblocks) also multiplies the recipe EU/t by 3; `amps === 8` (mass fabricator) uses `eutIncreasePerOC 2` and `maxOverclocks tier − 1`; `parallel` is 1.

    - `export function buildCandidates(pack: Pack, settings: PlanSettings, env: PlanEnv, leaf: LeafOracle, targets: StuffKey[]): CandidateGraph`

`buildCandidates` walks backwards from `targets` (breadth-first, keys visited once):
- A target is never buyable, whatever the oracle says. Every other good asks `leaf(key)`; a buyable good is a leaf and is not expanded. A non-buyable good is expanded through `pack.producers`, keeping recipes for which `acceptRecipe` is ok.
- `settings.recipeChoice[key]` restricts that good to the pinned recipe when the pin exists, produces the good and is accepted; otherwise the pin is ignored and a warning `{ code: 'stale-choice', key, text: '<Name>: the chosen recipe is gone or cannot run at <TIER>; using the best one available' }` is added.
- A consumed ingredient with one option is a direct coefficient. With several options it becomes `virtualKey(options)` with coefficient −1 (× chance) and one `convert` recipe per kept option (id `convert:<virtualKey>:<optionKey>`, coeffs `[[option, −amount], [virtual, +1]]`). Kept options: sorted by key; only the buyable ones if any option is buyable, else the first 8.
- A non-consumed ingredient adds its first option to `nonConsumed` and is not walked.
- A good whose producers were all rejected gets a `blocked` entry. The walk stops adding recipes after 20,000 and adds `{ code: 'graph-too-big', text: 'This chain is too large to plan in one go; mark some parts as "we already make this"' }`.

Results are cached per pack and env (`tier`, sorted `reachable`, `lowGravity`, `coilHeat`, sorted `excluded`), 32 entries.

    - `export function makeLeafOracle(pack: Pack, settings: PlanSettings, avail: Availability, prices: PriceTable, stopCost?: (key: StuffKey) => number): LeafOracle` — `expandItems` → not a leaf; `stopItems` → buyable at `settings.costOverrides[key] ?? stopCost?.(key) ?? prices.price(key)`, class `stop`; class `free`/`natural` → buyable at price; base item `direct`/`byproduct` → buyable at price; base item `derived` → buyable unless `settings.routeDerived`, class `derived`; base item `unavailable` → `{ buyable: false, cost: 0, leafClass: 'unavailable' }`; everything else → `{ buyable: false, cost: 0, leafClass: null }`.

    - `export function analyzeCosts(graph: CandidateGraph): Promise<CostAnalysis>` — YAFC-style dual LP (prior-art §3.4 step 2; learn-only reference, no code copied): one variable per good, bounds `[0, cost]` for buyable goods and `[0, 1e6]` otherwise, maximize `Σ c_g`, one row per recipe `Σ out·c − Σ in·c ≤ 0`; a value within 1e-6 of 1e6 becomes `Infinity`. `recipeCost(r, g) = (Σ inputs a·c − Σ other outputs a·c) / a_g` (byproduct credit), `Infinity` if any input is. Used only to rank alternatives and to price "we already make this" goods; the plan itself always comes from the main LP (Task 10).

### Task 10: Rate solver — lexicographic stages, loop guard, plain-words blockers

**Files:**
- Create: `src/server/planner/solve.ts`
- Test: `tests/unit/planner/solve.test.ts`

**Interfaces:**
- Consumes: `CandidateGraph`, `LpRecipe`, `GoodInfo`, `Rejection` (Task 7); `solveLp`, `LpModel` (Task 9); `PlanWarning` (Task 1).
- Produces (`src/server/planner/solve.ts`):
  - `export interface Blocker { key: StuffKey; reason: 'unavailable' | 'rejected' | 'no-recipe'; needTier?: number }`
  - `export interface Solution { status: 'ok' | 'infeasible'; runs: Map<string, number> /* recipe id (convert ids included) → runs per unit of demand time */; buys: Map<StuffKey, number>; sinks: Map<StuffKey, number>; rawCost: number; blockers: Blocker[]; warnings: PlanWarning[] }` — maps hold only values > 1e-9, rounded to 9 decimal places (`Math.round(x × 1e9) / 1e9`, so an exact 1 stays 1 and equal plans compare equal), inserted in sorted key order; `rawCost` is rounded the same way.
  - `export function solveLine(graph: CandidateGraph, demand: ReadonlyMap<StuffKey, number>): Promise<Solution>`
  - `export function findBlockers(graph: CandidateGraph): Blocker[]`

Main LP (prior-art §3.4, extent form; columns in fixed order: recipes by id, then buy columns of buyable goods by key, then sink columns of all goods by key; one equality row per good by key: `Σ a_rg·x_r + buy_g − sink_g = demand_g`):
1. **S1** minimize `Σ cost_g·buy_g` (least raw material, spec §3.3).
2. **S2** add `Σ cost_g·buy_g ≤ S1·(1 + 1e-9) + 1e-9`, minimize `Σ euPerRun_r·x_r` (power only breaks ties).
3. **S4** add `Σ euPerRun_r·x_r ≤ S2·(1 + 1e-9) + 1e-9`, minimize `Σ x_r + Σ buy_g + Σ sink_g` (canonical form).
4. **Loop guard** after S1: solve the same rows with every buy column fixed to 0 (free goods included). If that is feasible, the recipes with `x > 1e-9` in it make matter from nothing: ban them (drop their columns), add `{ code: 'free-loop', text: 'Ignored recipes that make <target names> from nothing (likely a recipe data loop): <recipe ids>' }` and start again at S1; at most 5 rounds.
5. **Infeasible** S1 → `status: 'infeasible'`, `blockers = findBlockers(graph)`, empty maps.

`findBlockers`: forward fixpoint "makeable" (buyable goods are makeable; a recipe fires when every good with a negative coefficient is makeable; its outputs become makeable), then a depth-first walk from each non-makeable target through the producers of non-makeable goods; a non-makeable good with no producer in the graph is a blocker: `unavailable` when its `leafClass === 'unavailable'`, else `rejected` (with the smallest `needTier` from `graph.blocked`) when it has a `blocked` entry, else `no-recipe`. Sorted by key, deduplicated, at most 5.

## Real-data amendments (2026-10-18, planner on the 2.9 export)

The planner now follows the investigation on branch `planner-realdata-fix`. Where these rules differ from the task text
or the final-review amendments above (rough-cost pruning, derived leaves at rough cost with a markup), these win:

- **Natural items.** A gathered ore-dictionary name from the curated list (not `slimeball`, `food`, `listAll`), or
  sticky resin or the vanilla slime ball; "no recipe makes it" does not count.
- **Multiblock gating.** A multiblock recipe runs only where availability has built the multiblock (its controller
  item is available); generator fuel maps never make goods.
- **Availability bootstrap.** An NBT variant counts for its plain item (GT tools); programmed circuits are available
  from LV. Availability ignores the `programmed-circuit-conversion` exclusion (it is the only way the export shows to
  the first Electronic Circuit).
- **Pruning.** The candidate walk estimates a raw cost per unit for every reachable good (cheapest-first, settled once
  each, equal costs by key so the export's order never matters) and keeps at most 3 producers and ore-dictionary
  options per good, within 2× the cheapest, producers grounded in goods settled before the output first. Cap 40,000.
- **Loop guard.** Recipes that consume nothing are sources, not loops; the guard fires only when the demand can be met
  with every purchase and source at 0 and bans the least-runs circulation that leaves a surplus; after the fifth ban
  the line is infeasible with one warning; banned recipes are named by machine and product.
- **Derived leaves.** Priced at their standalone cost (S1 of the cost model's graph, demand 1, byproducts sunk, no
  recipe consuming the target), repeated until no bought derived leaf is unpriced (6 rounds at most). One the cost
  model never walked is priced over a graph walked from it alone, never below its plain price. One only a chain
  through the target makes is no leaf. Cost overrides win. All of a plan's derived leaves share one warning.
- **S3.** Fewest recipes among the least-raw plans (MIP, node limit; reweighted L1 fallback), before power; a second
  MIP keeps that count and takes the least weighted free input (with what bought derived leaves' chains take), power
  and chains of bought derived leaves. S4 weighs a derived purchase by 1 + its chain's recipes.
- **Exclusions.** Defaults: recycling (also smelting a finished part back into its metal), massfab, replicator,
  scrap, lava-centrifuge (also electrolysing lava or stone/obsidian dust, the thermal refinery's lava filter, and every
  recipe that separates free inputs alone into ore materials) and `programmed-circuit-conversion` ("Programmed circuit
  back into circuits": crafting a programmed circuit back into a circuit), so the Electronic Circuit uses the circuit
  assembler.
- **Blockers.** An out-of-reach target whose only chain runs through itself gets its own unlock hint.
- **Acceptance.** `tests/unit/planner/real-acceptance.test.ts` and `real-pack.test.ts` (GTNH_LOCAL=1) hold on this
  host's exports.
- **Planner quality.** Plan 09 (`2026-10-19-09-planner-quality.md`, fix spec §5) amends the natural-item, pruning,
